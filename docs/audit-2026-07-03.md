# Code Audit Findings (2026-07-03)

Full-codebase audit of release-smith. This document tracks every finding with its
severity, location, and fix status. The branch `fix/audit-high-medium` addresses
all HIGH and MEDIUM findings; LOW findings are documented but intentionally left
out of scope for that branch.

Severity definitions:

- **HIGH**: silently produces wrong releases, loses data, or breaks the release
  pipeline in common configurations.
- **MEDIUM**: wrong behavior in realistic but narrower configurations, misleading
  failures, or security hardening in CI.
- **LOW**: edge cases, misleading warnings, or diagnosability gaps.

## High severity

| # | Finding | Location | Status |
|---|---------|----------|--------|
| H1 | Config `name` override silently breaks the dependency graph: propagation, rollup, topological sort, and dependency range updates all key by the overridden name while `workspaceDeps` holds real npm names | `config/src/workspace.ts`, `core/src/topo-sort.ts`, `core/src/releaser.ts`, `cli/src/pipeline.ts` | Fixed: `ResolvedPackage.name` now always carries the npm name; a new `displayName` (config override) is used for tags, changelogs, commit messages, and CI outputs |
| H2 | `release.yml` tags the synthetic PR merge ref instead of the real commit on main; `release-tags` never verifies HEAD against the PR merge commit | `.github/workflows/release.yml`, `cli/src/commands/release-tags.ts` | Fixed: workflow checks out `merge_commit_sha`; `release-tags` fails fast when HEAD does not match the PR's merge commit |
| H3 | Shared unpublished dependency gets the first dependent's baseline for all dependents, causing missed or duplicated rollup commits | `cli/src/pipeline.ts` | Fixed: commit queries are cached per (path, baseline) instead of per path |
| H4 | Release PR metadata regex only matches LF; GitHub normalizes edited PR bodies to CRLF, permanently breaking `release-tags` for that PR | `cli/src/commands/release-pr.ts` | Fixed: parser accepts CRLF and strips carriage returns before JSON parsing |
| H5 | No clean-working-tree guard: `git add -A` sweeps unrelated changes into release commits; failed runs leave half-written bumps that double-bump on retry | `cli/src/commands/release-pr.ts`, `cli/src/commands/release.ts`, `core/src/releaser.ts` | Fixed: release and release-pr refuse to run on a dirty tree; releaser stages only the files it wrote |
| H6 | `parseGitHubUrl` cannot parse repo names containing dots (e.g. `next.js`) or URLs with trailing slashes | `github/src/release.ts` | Fixed: parser accepts dots and trailing slashes, strips only a final `.git` suffix |

## Medium severity

| # | Finding | Location | Status |
|---|---------|----------|--------|
| M1 | No runtime config validation: wrong-typed values (e.g. `packages` as an array, `branches: {"next": "beta"}`) flow through unchecked casts and silently disable publishing or prerelease | `config/src/loader.ts` | Fixed: all fields validated at load time with descriptive errors |
| M2 | Single-package (`.`) projects ignore `publish`/`changelog`/`from` overrides and hardcode `publish: true` even for private packages | `config/src/workspace.ts` | Fixed: overrides respected; private defaults to `publish: false`, consistent with monorepo behavior |
| M3 | Mistyped config package keys are silently ignored while still flipping every unlisted package to `publish: false` | `config/src/workspace.ts` | Fixed: warning for config keys that match no discovered package |
| M4 | git `core.quotePath` octal-escapes non-ASCII filenames, breaking package path matching and `ignoreFiles` filtering | `git/src/diff.ts` | Fixed: `-c core.quotepath=false` on file-listing commands |
| M5 | Config read errors other than ENOENT (EACCES, EISDIR) are treated as "no config", silently releasing with defaults | `config/src/loader.ts` | Fixed: only ENOENT returns null; other errors propagate with the config path |
| M6 | Workspace glob resolution does not exclude `node_modules`, so `packages/**` patterns pick up third-party packages | `config/src/workspace.ts` | Fixed: `**/node_modules/**` ignored |
| M7 | Release existence check does not URL-encode the tag, so scoped-package tags (containing `/`) always 404 and CI retries fail with 422 | `github/src/release.ts` | Fixed: tag is URL-encoded; 404 is now distinguished from other errors |
| M8 | `createGitHubRelease` treats every GET failure (401, 403, rate limit) as "release does not exist" | `github/src/release.ts`, `github/src/client.ts` | Fixed: `GitHubApiError` carries the HTTP status; only 404 falls through to creation |
| M9 | Fixed groups inflate the version when graduating a prerelease to stable (one member computes 1.1.0, group lands on 1.2.0) | `core/src/version-calculator.ts` | Fixed: group members bump from their actual version, preserving semver graduation semantics |
| M10 | Numeric (`"1"`) or dotted (`"beta.x"`) prerelease identifiers make `bumpPrerelease` return the current version forever, wedging releases | `core/src/version-calculator.ts` | Fixed: sequence detection uses string prefix matching instead of parsed identifier comparison |
| M11 | `replaceVersion` corrupts wildcard and dist-tag ranges: `*` becomes `*1.3.0`, `latest` becomes `latest1.3.0` (invalid), `1.x` gets pinned | `core/src/releaser.ts` | Fixed: ranges without a concrete numeric base are left unchanged |
| M12 | Prerelease version drifts upward on every run when no stable tag exists (`1.1.0-beta.0` -> `1.2.0-beta.0` instead of `beta.1`) | `cli/src/pipeline.ts`, `core/src/version-calculator.ts` | Fixed: an in-progress prerelease continues its sequence when the computed target does not exceed its base |
| M13 | Unknown CLI flags are silently ignored (`--dry-runn` performs a real release); `--flag=false` on booleans parses as the truthy string `"false"` | `cli/src/index.ts`, command definitions | Fixed: unknown flags are rejected; string values on boolean flags are coerced or rejected |
| M14 | `release.yml` shell-injects `head.ref` into `run:`; branch names are attacker-influenced on fork PRs | `.github/workflows/release.yml` | Fixed: value passed via `env:` |
| M15 | `release.yml` permissions block omits `pull-requests: read`, breaking `release-tags` on private repos | `.github/workflows/release.yml` | Fixed: permission added |
